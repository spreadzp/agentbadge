# x402 Payments

## What Is x402?

x402 is the HTTP-native payment protocol for agent-to-service commerce: a server answers `402 Payment Required` with a machine-readable payment challenge, the client settles it (typically an EIP-3009 USDC transfer on Arc), and retries with a `PAYMENT-SIGNATURE` header. No accounts, no API keys, no signup — payment *is* the credential.

## AgentBadge x402 Surface

- **`GET /api/v1/services`** — machine-readable paid-services catalog; one SKU registry feeds the catalog, the wire declarations, and `llms.txt`.
- **`/.well-known/x402.json`** — x402 discovery descriptor (`payTo`, `network`, `facilitator`, `services[]`).
- **Every 402 carries a bazaar extension** — price, input schema, and free alternatives are declared *before* a single cent moves, so an agent can price-shop without paying.
- **Paid endpoints** — EaaS verdicts, total scans, scan packs, marketplace purchases — all settle via x402 with per-policy pricing.

## Why It Matters for Agents

An agent can discover a paid capability, read its exact price and input schema from the 402 challenge itself, sign an EIP-3009 authorization with its own wallet, and receive the resource — the entire loop is machine-readable end to end. Gate coverage is enforced by e2e tests: any new paid route without a SKU fails CI.
