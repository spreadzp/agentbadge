## 3. Divergences (all recorded, none fixed here — findings → EPIC-234)

**BUG (integrity hazard, not just a model gap):**
- **V04/V17/V33 — non-positive amounts reserved.** `amountUsd: 0 | -50 | -0`
  passes the gate and lands in the ledger as `settled`. Negative/zero
  reservations corrupt window sums downstream. → 234 candidate: enforcer
  must reject `!finite || ≤0` before reserve.
- **V29 — `"10"` (string) accepted.** A non-numeric wire amount reaches
  `begin()`, `amountUsd > perTx` is false, entry written with a string
  amount → window math degrades. → 234 candidate: type-check `amountUsd`.

**MODEL (semantic gap, arguably intentional):**
- **V25/V28/V34 — denied but wrong first-failure check.** We answer
  `CAP_EXCEEDED` where MMF says `NON_POSITIVE`/`EXPIRED` — order of
  checks differs; the spend IS blocked either way.
- **D03 — resolved post-234-42.** `validateDelegateInput` now strict-
  rejects a widening `spendCapUsd` (throw → `invalid` match); was
  silent `min`-clamp under 234-32.
- **D04–D12 — widening on unmapped bound dims.** `invalid` expected
  for child currency/payees/velocity/budget/expiry widening and
  revoked-parent delegation; the delegate model checks only
  `max_amount` vs owner perTx — other parent bounds are not
  represented (see `parent_extra_bounds`, `revocation` dims).
- **D14–D16 — delegate path lacks expiry/velocity/budget dims.** Only
  perTx + owner-suspension exist on the delegate path.
- **V31/V32 — `"1.0"`/`"1e0"` accepted.** Lexical amount class has no
  representation on our `number` API (D-255-Q16, flagged not emulated).

**NOT_MAPPABLE (dimension absent — reported, not emulated):**
- V03/V25-component `EXPIRED`, V07/V30 `CURRENCY`, V09 `PAYEE`,
  V27 fractional, V36 pre-eval rejection, D18 claim/settle steps.

**GATE_EXCEPTION:**
- V21 `registry.unavailable` → `walletStore.get` throws → Hono 500.
  Fail-closed (request dies) but NO structured deny/evidence record —
  matches the known "registry throw without deny evidence" 234-candidate.

**Own-invariant (excluded from MMF counts):**
- Replay probe: `refId` sent twice → **two** settled entries, fresh
  `sp_` ids. No dedup key exists. → 234 candidate (double-reserve).

## 3. Lifecycle findings (→ EPIC-234)

- **Velocity undercount via void (L05, L09) — BUG.** Our `windowCount`
  counts reserved+settled; `released` drops out. MMF counts *issued
  authorizations* — so authorize→void cycling frees the rate-limit
  slot indefinitely. A limiter evadable by void isn't a limiter.
  L09 doubles with missing deny-replay (stored denials don't exist).
- **No tx_id dedup / stored decisions — MODEL.** Every repeat `tx`
  re-reserves under a fresh `sp_` id (same_params, diff_amount,
  diff_payee, post-settle, post-void all re-decide). REPLAY and
  TX_CONFLICT cannot be emitted. Replay matrix recorded per vector.
- **Settle without CLAIMED — MODEL (L25).** `settleEntry` moves
  reserved→settled directly; MMF requires the claim handshake
  (dispatch-slot consumed). We can't express "claimed but rail
  declined" — the `cancellation`-ref gate is absent too (L26).
- **Idempotent settle — PARTIAL match.** Repeat `settle` returns
  false but the entry stays `settled` → final state matches MMF.
- **Cross-mandate tx_id — MODEL (L27).** mB reusing mA's tx_id is
  per-wallet namespaced in our ledger → reserves, no TX_CONFLICT.
- **Budget `total_budget` without window — NOT_MAPPABLE (L04).**
  No window ⇒ no SpendCaps field ⇒ spend allowed where MMF denies.

# Crypto/evidence track (SLICE-255-4) — `results/crypto.json`

9 vectors: 6 `credential.json` (§7 Ed25519 credentials) + 3
`evidence.json` (§5.6 canonical records + SHA-256 chain).

**Honesty note up front:** prod auth = EIP-191/ECDSA wallet-sig.
Ed25519 credentials and the MMF evidence hash chain **do not exist in
production**. `production_path` names the test-lib
(`tests/conformance/mmf/lib/mmf-canon.ts` + `@noble/curves/ed25519`),
and the prod-side dimensions are all `None`. A PASS here means
"our canonicalizer reproduces the spec byte-for-byte" — never
"prod conforms".

## 1. §7 verification semantics

- Signed payload rebuilt from the credential's own claimed fields
  (`mandate_id|agent|bounds_hash|expires_at`, len-prefixed) — NOT
  from the expected mandate. Bindings checked separately.
- Tampered bindings fail twice: signature (payload changed) + the
  specific binding check. Correct failed-check attribution:
  C02 `["signature"]`, C03 `["signature","bounds_hash"]`,
  C04 `["issuer_key"]` (sig verifies under the wrong embedded key),
  C05 `["signature","agent_binding"]`, C06 `["signature","mandate_binding"]`.

## 2. Numbers (9 vectors)

| Status | n | Vectors |
|---|---|---|
| PASS | 9 | C01–C06, E01–E03 — all Exact |

- C01: pubkey, bounds payload/hash, signed payload and Ed25519
  signature all byte-exact vs pinned values (deterministic signing).
- C02–C06: every tamper vector rejected with correct check attribution.
- E01–E03: all payloads + record hashes + chain head byte-exact
  (incl. null-amount→`invalid`, absent-field→`0:`, UTF-8 byte lens,

# Own invariants (SLICE-255-5) — `results/own-invariants.json`

Not MMF vectors — `source:"own-invariant"`, excluded from the
conformance counts. These probe OUR guarantees directly.

## 1. Race probe (D-255-Q22) — OBSERVED, not theoretical

`begin`: `registry.get → checkEnvelope(listByWallet) →
insertReserved(insert)`. The check and the insert are separate
awaits; nothing atomic joins them.

| Backend | Setup | Result |
|---|---|---|
| db-barrier (stub repo, listByWallet blocks until all 8 callers arrive) | dailyUsd $100, 8×$20 parallel | **8/8 reserved, $160 — $60 overshoot**; sequential baseline 5/8 |
| memory (no barrier, plain Promise.all) | dailyUsd $100, 32×$10 parallel | **32/32 reserved, $320 — $220 overshoot**; sequential baseline 10/32 |

**The memory-backend result matters.** envelope.ts L194-200 calls the
backend "atomic-enough" claiming sync backends "can't interleave
between the awaits (microtasks only)". Empirically false: each
`begin` coroutine interleaves at every await boundary — all 32
checkEnvelopes ran before any insert landed. A single-process memory
ledger overshoots 3.2×. With a real DB round-trip the window is
strictly wider. `OWN-1` → EPIC-234 (atomic check+insert /
conditional insert / serializable txn).

Post-settle verified: settling the overshoot reservations still
counts → next begin denied (cap state correct, just exceeded).
Observation ≠ proof of atomicity either way — we record what
happened.
